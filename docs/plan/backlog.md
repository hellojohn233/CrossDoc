# Backlog

- **P1 · Two-stage retrieval:** line-level blocks let a multi-term query match one line, but a query whose terms sit on different lines still finds nothing. Add a relaxed pass that matches a single query feature when the strict pass returns no result, keeping strict results first so the current ordering is unchanged.
- **P1 · Review skill exposure:** `review-001` is still pending, so the agent cannot start a consistency review on request even though the tools exist.
- **P2 · Recall cost:** `recallCandidates` compares every pair of claims, so the recall pass is O(n²). It is fine for a handful of documents and the only stage that needs work once a corpus grows: build an inverted index over rare tokens, or a blocking key, so only plausible pairs are compared.
- **P2 · Adjudication throughput:** the adjudicator sends candidate pairs to the model in fixed batches of eight, one request at a time. Tune the batch size and run the batches concurrently once the corpus produces enough candidates to matter.
- **P2 · Recall coverage:** recall keeps a pair when it carries a difference signal or shares enough tokens, so a contradiction expressed with completely different wording can still be missed. Measure the recall rate against a labelled corpus before tightening it.
- **P2 · PDF rendering coverage:** `scripts/verify-pdf-page-render.mjs` uses empty pages, so it validates PNG structure and dimensions but not visible rendered pixels. Add a visible-content fixture and pixel assertion in a follow-up renderer verification task. See `docs/plan/reviews/pdf-002-001.md`.
- **P2 · Retrieval corpus work bound:** `searchDocument()` caps query and document count, but currently scans and ranks every block before applying the excerpt cap. Add an aggregate block/text-size limit or bounded top-k scan for very large libraries. See `docs/plan/reviews/skill-001-001.md`.
- **P2 · Model-selected parse order:** Pi preserves the order of parse tool calls emitted by the model, while the model is instructed to emit calls in selected-file order. If a future UI needs a hard guarantee independent of model output, add a batch parse boundary that sorts by the server's original request scope. See `docs/plan/reviews/agent-002-001.md`.
- **P2 · Web session and scan-budget edge coverage:** Add tests for six busy sessions and seventh-session rejection/idle eviction, plus a session-wide text budget crossed only by scan-page appends. See `docs/plan/reviews/web-001-001.md`.
- **P2 · Web SSE backpressure and recovery coverage:** Bound slow or numerous SSE listeners and test event-ring compaction snapshot replay. See `docs/plan/reviews/web-001-001.md`.
- **P2 · Web terminal read states:** Replace the overview placeholder after all-failed/cancelled/no-text runs and expose a reconnect action after terminal EventSource failure. See `docs/plan/reviews/web-001-001.md`.
- **P2 · SQLite library symlink containment:** `resolveDataPath()` checks lexical containment but not symlink targets. Before serving indexed source/Markdown paths, verify their real paths remain under the data directory. See `docs/plan/reviews/storage-001-001.md`.
- **P2 · Scan pages that also carry selectable text:** page classification only counts the whole page's characters, so a page with a text header and a scanned body is classified as text-native and its body never reaches the vision model. Classify by region, or lower the native-text threshold and let the vision path fill the gaps.
- **P2 · Review console page width:** the review console is a full-bleed three-column workbench while the other views are constrained to `--page-width`, so the header rule and the console edges do not line up on wide screens. Constrain the console or align the header to the same grid once the review flow is exercised end to end. See `docs/plan/tasks/ui-001-navigation-and-visual-hierarchy.md`.
- **P2 · Two-column layouts:** the line grouping merges runs that share a baseline, so two columns on the same baseline become one line. Break a line when the horizontal gap between adjacent runs exceeds a threshold.
