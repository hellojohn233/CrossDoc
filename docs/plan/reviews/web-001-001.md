# Review: web-001

## Findings

- **P2 · non-blocking** — The new integration script covers duplicate parse calls, the prior concurrent archive-failure rollback sequence, and per-document scan text overage with archive deletion. It does not fill all six session slots with busy jobs to verify the seventh request is rejected, verify idle-session eviction at capacity, or cross the per-session character limit specifically through scan-page appends. Add those cases to make the new limits' edges explicit.
- **P2 · non-blocking** — The retained event ring has per-session and global byte caps, but live SSE delivery does not apply backpressure or cap listeners. `emit()` ignores `response.write()`'s backpressure result, and every open response remains in `session.listeners`. Slow or numerous clients can therefore accumulate socket output buffers even while the replay ring stays within its byte budget.
- **P2 · non-blocking** — The API detects replay compaction and sends a current snapshot, but `verify:web-read` only tests ordinary `Last-Event-ID` replay; it does not force the 500-event or byte limit and verify snapshot recovery while a session is active.
- **P2 · non-blocking** — When the initial run ends with no assistant overview (all files fail, cancellation, or a model response with no text), the overview area remains “正在读取文档…”. The `done` handler updates status and controls but does not replace this placeholder with the failure/cancellation state. Also, on a terminal EventSource failure the notice says “请重新连接”, but the UI exposes no reconnect action; native EventSource retries only while the connection remains reconnectable.
