# Review: review-002

## Findings

- **P1 · resolved** — The conflict score was a similarity measure that was re-labelled as a verdict. `compareClaims` set `score: Math.max(overlap, oppositePolarity ? 0.7 : 0)` and `verifyConflicts` marked any pair with `score >= 0.7` as `verified`, so two documents holding the identical sentence scored 1.0 and became a verified conflict, while a genuine difference in a value was ranked no higher than a shared clause. The score is now the adjudicator's confidence that a pair really contradicts, and it is produced by a stage that reads both statements instead of their token sets.
- **P1 · resolved** — Chinese claims were never compared. `tokenSet` split on whitespace and dropped tokens shorter than two characters, so a whole Chinese sentence became a single token and the overlap was near zero; the negation pattern used `\b`, which never matches between two CJK characters, so `不得` was invisible. The recall stage now uses character bigrams for CJK runs and matches CJK negation terms as substrings.
- **P1 · resolved** — `inferKind` returned before resetting `lastIndex` on two global-flagged patterns, so a date sentence that followed another date sentence was classified as `fact` or `amount`. Both patterns lost the global flag and the manual resets were removed.
- **P1 · resolved** — The evidence contract was implicit. Nothing checked that a reported conflict still pointed at its own claim, so a conflict could survive with a missing or mismatched quote. The verification stage now dismisses any conflict whose evidence is missing, empty, or points at another document, because an uncitable finding is worse than a missing one.
- **P2 · accepted** — Recall is O(n²) over claims. The pair comparison is cheap and the corpus is small, so the cost is recorded in the backlog rather than optimized now. It is the only stage that needs an index at scale.
- **P2 · accepted** — A pair the adjudicator omits is treated as consistent. Silence is not evidence of a contradiction, so the conservative reading is the correct one; the rationale records that no verdict was returned.

All four real contradictions in the corpus are found — payment terms 45 vs 90 days, contract value USD 120000 vs 150000, effective date March 1 vs April 1, and counterparty Bright Harbor vs Cedar Point — and the six dismissed candidates are headings and clauses that agree.

- The ledger model was rebuilt from the live response: 7 entries in 待处理, 6 in 已排除, every entry carrying two evidence ids that match its own claim evidence.

## Conclusion

**pass** — the inverted conflict semantics are resolved. Recall decides only which pairs to read, the model decides only whether a pair contradicts, and the rules decide only whether the finding is citable. The `/api/review` response body is unchanged apart from the additive `judgeSource` and `warning` fields, so the ledger needed no change.
