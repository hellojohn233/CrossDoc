# Review: review-003

## Findings

- **P1 · resolved** — Recall required the two sentences to share vocabulary, so a contradiction written with different wording was never a candidate. Alignment now runs on key data from a fixed vocabulary, so the same kind of data lines up across documents by construction instead of by shared words.
- **P1 · resolved** — The pipeline compared every pair of claims, which is O(n²) and was recorded as a backlog item. Alignment is O(n) in key data points and there is no pairwise claim comparison anywhere in the pipeline.
- **P1 · resolved** — The rule fallback never found `USD 120000`, because the amount pattern only allowed a currency suffix, and it never found a value like `1,200.0` because the comma was treated as punctuation. Both are fixed and covered by assertions.
- **P1 · resolved** — Value normalization turned `USD 1,200.0` into `usd 1 200 0` and treated `the analytics platform` and `analytics platform` as different values. Normalization now strips digit-group separators and trailing zeros before punctuation, and ignores a leading article.
- **P1 · resolved** — The first extraction pass produced values at inconsistent granularity (`all undisputed invoices within 90 days of receipt` against `45 days`) and split one fact into two items (`Northwind Analytics` and `Bright Harbor Ltd.` against `Northwind Analytics and Bright Harbor Ltd.`). The prompt now fixes both, and the alignment keeps one value per document and key.
- **P2 · accepted** — The key vocabulary is a fixed list. A key outside it is kept and flagged as custom, but custom keys align by exact name only, so two documents that name the same custom thing differently will not line up. Recorded as a follow-up in the task document.
- **P2 · accepted** — Key data is extracted from the document text, so a value that only appears in a table or on a scanned page can be missed. The scanner already routes scan pages through the vision model; wiring that text into the extraction prompt is future work.

- The full suite passed: `verify:conflict-diff`, `verify:document-ingest`, `verify:scan-page-blocks`, `verify:storage`, `verify:document-search`, `verify:web-read`, `verify:pdf-page-render`, `verify:pdf-vector-classification`, `verify:agent`, `verify:agent-parallel`.

The four real contradictions are found — counterparty, contract value, effective date, payment term — each reported once per key. The one dismissed candidate is a confidentiality clause stated at two levels of detail.
- A live Chinese check through the same model found all three planted contradictions — 不得 against 可以 on the service scope, 60 days against 90 days on payment, 人民币 100000 against 150000 on the contract value — each with a Chinese rationale.

## Conclusion

**pass** — the review now asks whether the key data lines up, not whether two sentence chunks share words. The model reads each document once, the alignment is a pure function over a fixed key vocabulary, the verdict comes from the model, and the rules only check that a finding is citable. The `/api/review` response body is unchanged apart from the additive `judgeSource` and `warning` fields, so the ledger needed no change.
