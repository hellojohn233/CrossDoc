# Review: ui-004

## Findings

- **P1 · resolved** — The review history sat under the document list, so the product's main output looked like a section of document management. `审查记录` is now a header tab of its own, and the Library holds documents only.
- **P1 · resolved** — Opening a stored review landed in the console with the wrong tab marked: the console is reached from the upload flow and from the history, and the header now says which one. `setView()` takes a tab override, and a review opened from the history leaves `审查记录` marked.
- **P1 · resolved** — `返回阅读` was offered on a stored review that has no running read behind it, and clicking it asked a session that was not there. It is hidden when the console was opened from the history.
- **P2 · resolved** — The history was rendered with the Library's row style, which sorts everything into equal columns. A review is one row with a heading (the document titles), a line under it (the counts and the time), and `打开` to the right — the same hierarchy the skill list uses.
- **P2 · accepted** — The history is a flat list with no search and no filter. With many reviews it is long, and the user reads titles to find one.
- **P3 · accepted** — A stored review can be opened but not re-run. The skills are read at the start of a run, so a re-run with today's skills is not the same review.
