# Review: ui-006

## Findings

- **P1 · resolved** — The built-in skills were invisible, so the rules the review follows could not be read. They are now listed in their own block under the user's own skills, and `GET /api/skills/builtin` returns their bodies and the files they point at.
- **P1 · resolved** — A built-in skill could have been edited from the page. The built-in rows offer `查看` only, the detail page says `内置 skill · 只能查看`, the edit action is not rendered for them, and `PUT /api/skills/<builtin name>` still answers 409.
- **P1 · resolved** — A skill was edited, not read. One row led straight to a form. Now a skill opens as a document — the Markdown, rendered — and `编辑` turns that into the source, where `保存` writes it and `取消` goes back.
- **P2 · resolved** — A skill body is text someone can type, and a user skill can come from a file the user brought along. The renderer escapes the text before it marks it up, and a link is only kept when the target is an ordinary web address.
- **P2 · accepted** — The renderer covers what a skill actually uses: headings, paragraphs, lists, quotes, code, rules, and the inline marks. A table or a deeply nested list is not rendered as the author wrote it.
- **P3 · accepted** — A built-in skill cannot be changed from the page at all, not even by the developer. Changing one means changing the file in the repository, which is the point.

## Verification

- `npm run typecheck` passed.
- `npm run build` passed.
- The inline module script parses (`node --check` on the extracted script).
- `npm run verify:markdown` passed with thirteen checks: headings by level, paragraphs, ordered and unordered lists, bold, italic and inline code, a code block kept verbatim, a quote, a rule, HTML escaped in a paragraph and in a code block, an ordinary link kept with `rel="noreferrer"`, a `javascript:` link dropped, inline marks inside a list item, and the escaping of quotes.
- `npm run verify:user-skills` passed with nineteen checks, the new one covering the built-in endpoint: the built-in skills listed with their bodies, a built-in skill refusing a write with 409, and its body unchanged afterwards.
- The rest of the suite passed: `verify:skills` (15), `verify:review-semantics` (17), `verify:library-delete` (9), `verify:web-read`, `verify:storage`.
- Headless Chrome render: the skill page shows both blocks; the built-in detail page renders the Markdown of `consistency-review` with no edit action; the user's own detail page renders `prospectus-review` with an `编辑` action; the edit state shows the source in a text area with `保存`, `取消`, and `删除`.
- The secret scan is clean.

## Conclusion

**pass** — the built-in skills can be read and cannot be written, and a skill is read as a document before it is edited as source.
