# Review: review-005

## Findings

- **P1 · resolved** — The set of skills was a literal union in `src/agent.ts`, so adding a skill meant editing TypeScript. The skills are now discovered from `.agents/skills/` and the parameter is a free string. A test writes a skill into a temporary directory and loads it without a code change.
- **P1 · resolved** — The model could not see which skills existed. The system prompt now carries the `<available_skills>` index, with name, description, and location per visible skill.
- **P1 · resolved** — A skill without a description was loaded anyway, and a malformed front-matter produced no signal. Description is now required, names are validated against the specification's rules, and both raise diagnostics.
- **P1 · resolved** — The review depended on the model remembering to call `load_document_skill`. The procedure is now injected into the first turn, so a review cannot run without it. The run got faster as a side effect: 42s to 31s.
- **P1 · resolved** — The two child skills were visible in the index, so the model could load `conflict-adjudication` instead of following the procedure. They carry `disable-model-invocation: true` now and are named by their parent.
- **P2 · accepted** — `scripts/` in a skill directory is not supported. Pi's skills may bundle executable code, but the CrossDoc agent has no shell and no filesystem tool on purpose. A skill that needs a capability gets a tool for it, not a script.
- **P2 · accepted** — The loader does not honour `.gitignore` the way Pi's does; it skips dot-directories and `node_modules`. The skills directory holds one file per skill, so nothing has been shadowed by it.
- **P2 · accepted** — A criteria change is still measured by a live run rather than by a corpus. Recorded as a backlog item.

## Verification

- `npm run typecheck` passed.
- `npm run build` passed.
- `npm run verify:skills` passed with thirteen checks: no loader diagnostics, the name rules and the directory name matching the declared name, the description, the length of `SKILL.md`, the existence of every referenced file, discovery of a skill written into a temporary root, the absence of a hardcoded list in `src/agent.ts`, a skill without a description being dropped while an invalid name raises a diagnostic, the index holding exactly the visible skills, the two child skills being hidden, the deterministic injection, the front-matter parser, and the path confinement of `read_skill_file`.
- `npm run verify:review-semantics` passed with seventeen checks, including a new one that asserts the review procedure is in the first turn of the conversation.
- The full suite passed: `verify:conflict-diff`, `verify:document-ingest`, `verify:scan-page-blocks`, `verify:storage`, `verify:document-search`, `verify:web-read`, `verify:pdf-page-render`, `verify:pdf-vector-classification`, `verify:agent`, `verify:agent-parallel`.
- A live `POST /api/review` over the three example contracts (MiniMax-M3.1-Flash) returned 4 conflicts, all four verified, in 31s. The agent loaded the two child skills in order and read both reference files.
- A live Chinese check through the same model found all three planted contradictions in 32s.

## Conclusion

**pass** — CrossDoc now uses Pi's skill mechanism rather than the shape of a skill file: discovery instead of a list, an index instead of prose, validation instead of silence, and a deterministic invocation instead of a request the model might ignore. The skill files are in the standard location and the standard format, so the same directories work under the Pi CLI.
