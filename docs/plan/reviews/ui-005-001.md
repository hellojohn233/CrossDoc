# Review: ui-005

## Findings

- **P1 · resolved** — The archive could not be emptied by the user. Every read archives the document and keeps every upload, so the local archive filled with copies nobody wanted, and the only way to remove one was to ask. `设置` now has an `归档存储` block that lists every archive and removes one or all of them.
- **P1 · resolved** — The archive was shown through the document list, which folds the copies of one content into a single row. The archive block folds nothing: archives that share content sit in one group, and each archive is a row with its own time and content hash. The block exists to show what is stored.
- **P1 · resolved** — A removal could have left the index and the files disagreeing. `DELETE /api/library/:id` removes the directory and the row together, and `DELETE /api/library` empties the whole index rather than deleting row by row, so a stray row cannot survive the cleanup.
- **P2 · resolved** — An id that tries to point outside the archive directory was a risk. The server only accepts a UUID, and the storage layer refuses an id that is not a plain name and checks that the resolved directory stays under the library root.
- **P2 · resolved** — The archive had no home. It sat under the document list, which read like document management. It is now a block in the settings view, next to the models, and the tab is called `设置`.
- **P2 · accepted** — A removed archive is gone. There is no trash and no undo, so both removals ask for a confirmation in the UI.
- **P3 · accepted** — Removing an archive does not remove the reviews that read it. A stored review keeps its own body, so it can still be opened after the documents behind it are gone.
